# PromoBot

[![CI Build](https://github.com/MikebangSfilya/promoBot/actions/workflows/ci-build.yml/badge.svg)](https://github.com/MikebangSfilya/promoBot/actions/workflows/ci-build.yml)

Telegram-бот для управления промокодами, построенный на базе [goSadTgBot](https://github.com/kozalosev/goSadTgBot). Работает на версии Go 1.24

Русская версия | [English](../README.md)

## Описание

PromoBot позволяет администраторам создавать промокоды для [DickGrowerBot](https://github.com/kozalosev/DickGrowerBot).

## Возможности

- Создание промокодов с настраиваемыми параметрами
- Просмотр таблицы всех промокодов
- Контроль доступа на основе конфигурации пользователей

## Установка

### Конфигурация пользователей

Создайте файл `users.yaml`. Пример создания конфигурации находится в `cfg/users.yaml.example`

### Переменные окружения

Задайте переменные окружения, полное описание находится в `env.example`

## Запуск

```bash
make up
```

Если хотите запустить только инфраструктуру в Docker контейнерах и запустить бота локально:

```bash
make up-infra run
```

## Команды бота

Бот работает только в личных сообщениях. В группах все команды, кроме `/help`,
отклоняются, а обычные сообщения игнорируются.

Все команды доступны только пользователям со статусом admin:
- `/promo` - Создать новый промокод
- `/get` - Показать все промокоды
- `/stats` - Полная статистика по конкретным промокодам
- `/edit` - Изменить существующий промокод
- `/delete` - Удалить существующий промокод

`/help` доступна всем и рассказывает, что бот делает в личке и в группах.

## Еженедельный отчёт по активациям

Раз в неделю бот может присылать в чат админов сводку по промокодам, созданным за
последние `REPORT_PERIOD_WEEKS` недель: что было создано (с автором, прибавкой к
длине, изначальным количеством активаций, датой создания и сроком действия), какие
из этих промокодов активировали и сколько раз, а какие не активировали ни разу.

Период намеренно шире одной недели: промокод может быть создан в любой момент, и
более широкое окно позволяет учесть активации промокодов, созданных незадолго до
предыдущего отчёта.

Функция включается по желанию — без `ADMINS_CHAT_ID` она отключена, и при запуске
бот пишет предупреждение в лог. Параметры `ADMINS_CHAT_ID`, `REPORT_CRON`,
`REPORT_PERIOD_WEEKS` и `REPORT_LANG` описаны в `.env.example`.

Кто и когда создал промокод, берётся из журнала аудита (`AUDIT_LOGS_DIR/audit.json`) —
это единственное место, где такая информация сохраняется, поэтому каталог должен
переживать перезапуски. Время активаций берётся из колонки `activated_at` таблицы
`Promo_Code_Activations`, которую заполняет DickGrowerBot при активации промокода;
этот бот её только читает и дублирует в своей миграции, чтобы созданная с нуля база
соответствовала общей схеме.

Сразу за ним вторым сообщением приходит список тех, **кто менял промокоды** за последние
`REPORT_EVENTS_PERIOD_WEEKS` недель, сгруппированный по людям: кто что создал, изменил или
удалил и какие поля затронуло изменение. Этот период должен совпадать с интервалом между
отчётами — в отличие от периода отчёта об активациях он не должен перекрываться, иначе одни
и те же события будут повторяться в каждом отчёте.

Отчёт, который не помещается в одно сообщение Telegram, разбивается на страницы: заголовок
повторяется на каждой с номером страницы. За один отчёт отправляется не более
`REPORT_MAX_PAGES` сообщений (по умолчанию 3), чтобы активная неделя не завалила чат;
всё, что не поместилось, отбрасывается, а на последней странице указано, сколько именно.
